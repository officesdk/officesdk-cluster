# 产品与接入场景

[返回首页](../README.md) · 简体中文 · [English](product.en.md)

石墨办公文档中台私有部署面向已有业务系统的企业。以合同审批为例，合同编号、审批流程和人员权限仍由合同系统管理。用户在合同详情页打开编辑器，石墨处理中台内的协同内容，合同系统可以根据编辑事件更新最近修改时间。[产品介绍](https://shimo.net/products/office-sdk) · [保存与更新机制](https://support.shimo.net/apidoc/docs-site/6000018/doc-338253)

## 按文件用途选择接入方式

| 业务需要 | 接入方式 | 首次验证时看什么 |
| --- | --- | --- |
| 在审批页查看已上传的 Office 附件 | 保留原文件，为预览服务提供文件标识、读取权限、扩展名和可获取原件的地址 | 有权用户能看到指定版本的附件，无权用户被拒绝。[文件预览](https://support.shimo.net/apidoc/docs-site/6000018/doc-338710) |
| 多名经办人共同起草合同 | 创建一份协同文件，将业务记录与 `fileId` 关联，在详情页加载编辑器 | 两名编辑者看见对方的修改，重新打开后内容仍在。[协同编辑](https://support.shimo.net/apidoc/docs-site/6000018/doc-338711) |
| 把已有合同导入协同编辑，再把定稿导回档案系统 | 发起导入或导出任务，检查任务进度，成功后再把结果交给下一环节 | 用带表格、图片的真实脱敏样本往返一次，比对版式和内容。[导入说明](https://support.shimo.net/apidoc/docs-site/6000018/doc-338270) · [导出流程](https://support.shimo.net/apidoc/docs-site/6000018/doc-338271) |

评估格式时分别核对能否预览、导入编辑、导出目标格式，再用本企业的样本验证。[官方格式清单](https://support.shimo.net/apidoc/docs-site/6000018/doc-338240)

## 哪一方负责什么

```mermaid
flowchart LR
    A[业务前端] -->|打开预览或编辑器| C[石墨文档中台]
    B[业务后端] -->|携带应用签名调用 API| C
    C -->|回调查询用户、文件和权限| B
```

- **业务前端**提供文件入口、编辑器容器和业务操作按钮，通过 JS SDK 打开指定文件。
- **业务后端**维护用户、业务文件 ID 和权限，生成访问凭证，实现中台可访问的回调。已有附件的原件下载地址也由业务侧提供。
- **文档中台**处理预览、协同编辑、导入导出，通过回调查询用户和文件信息，并按业务场景推送事件。
- **企业运维**负责部署环境、域名、证书、容量和备份恢复，按交付版本维护中台服务。[部署与验收](deployment.md) · [运行维护](operations.md)

具备中台访问地址和应用凭证后，可按[接口接入指南](integration.md)完成第一次联调。
