# 私有部署与验收

[返回首页](../README.md) · 简体中文 · [English](deployment.en.md)

本指南帮助实施人员选定部署方式，安装文档中台，并交付一个可供业务系统联调的环境。

## 选择部署方式

| 当前环境 | 起点 |
| --- | --- |
| 首次验证，已有一台符合要求的服务器 | 从 K8s 单机在线部署开始。[单机部署](https://support.shimo.net/apidoc/docs-site/6000017/338578m0) |
| 需要多节点运行 | 通过安装器新建 K8s 集群。[集群部署](https://support.shimo.net/apidoc/docs-site/6000017/338621m0) |
| 已有集群、需要离线安装或使用外部中间件 | 按交付版本选择对应部署方式，核对镜像、存储和中间件要求。[官方部署运维文档](https://support.shimo.net/apidoc/docs-site/6000017/338575m0) |

## 部署前准备

| 核对项 | 单机在线验证 | 新建集群 |
| --- | --- | --- |
| 节点 | 1 台空白服务器 | 至少 3 台，确认节点互通和时间同步 |
| 计算与存储 | 参考值为 16 核、32 GB 内存、根分区 100 GB、独立挂载的 `/data` 可用 300 GB | 每个节点分别满足左侧要求，按文档规模和并发规划容量 |
| 网络 | 管理端可访问安装器，业务侧可访问中台域名，中台可回访业务后端 | 另需确认 Pod、Service 与现有网络地址段无冲突 |
| 安装物料 | 匹配 CPU 架构的安装器、配套 K8s 产品发行包 | 另需准备所有节点信息、角色与 SSH 连接方式 |

以上资源取自官方环境速查。实施前按交付版本核对操作系统、CPU 架构、挂载路径、端口和资源要求。为中台配置实际访问域名和 HTTPS 证书，限制安装器管理入口的访问范围。[系统环境要求速查](https://support.shimo.net/apidoc/docs-site/6000017/338337m0)

## 安装器流程

1. 从石墨交付方取得安装器与发行包。把安装器上传至安装节点，在服务器上按对应版本说明启动 Web 安装器，记录其显示的访问地址。
2. 在管理电脑上打开安装页面，选择本机保存的发行包并核对校验结果。填写访问域名、节点和 SSH 信息、命名空间、数据目录及中间件选项。
3. 在部署概览核对目标节点和磁盘，执行环境检查。修复失败项后重新扫描，确认警告对本次环境的影响再启动安装。
4. 保存部署结果中的管理后台和 Demo 入口、访问域名、发行包版本、命名空间。凭证放入企业密码管理系统。按交付流程完成 License 和业务应用配置。[部署步骤与安装器说明](https://support.shimo.net/apidoc/docs-site/6000017/338575m0)

## 分两次验收

| 阶段 | 操作 | 通过依据 |
| --- | --- | --- |
| 部署交付 | 检查节点和工作负载，打开交付的后台及 Demo | 节点 Ready，长期服务 Pod 就绪，初始化任务成功完成。管理员能登录并查看机器和授权信息 |
| 业务联调 | 在真实业务入口用测试账号创建、编辑并重新打开同一文件，再换只读账号验证 | 同一文件的修改可见，协作者看到一致内容，只读用户无法修改。需要附件预览或格式转换时，另用约定样本验收对应功能 |

在连到目标集群的管理端，可先执行以下只读检查。`NAMESPACE` 替换成安装器记录的实际命名空间。

```sh
kubectl config current-context
kubectl get nodes
kubectl -n "$NAMESPACE" get pods,jobs
```

交接记录应包含环境、版本、验收时间、文档类型和失败项，便于升级后对照复测。[接入第一份文档](integration.md) · [运行维护手册](operations.md)
